## 1. 这个软件能否作为申请基础

目前已有可运行程序、四步操作界面、独立 Git 仓库和可复现检查，可作为软件著作权登记的材料准备基础。是否取得登记还取决于实际著作权归属、独立开发或授权情况以及材料完整性；功能多少和页面采用什么布局，并不是统一申请表的格式要求。

登记材料包括统一申请表、源程序和文档鉴别材料、权属及身份证明。通常交存代码与一种文档各自开头和末尾连续 30 页；各自不足 60 页则完整提交。一般代码每页至少 50 行、文字文档每页至少 30 行，特殊情形按登记机构要求处理。依据：[国家版权局《计算机软件著作权登记办法》](https://www.ncac.gov.cn/xxfb/flfg/bmgz/202410/t20241015_869486.html)。

软件保护涉及程序与相关文档的表达，开发所用的思想、操作方法、数学概念等不属于该条例的保护范围。申请应落实到自己的实际程序和文档。[《计算机软件保护条例》](https://www.cac.gov.cn/2013-02/08/c_12648744.htm)。

## 3. 可用于申请表的功能说明草案

本软件用于视频和图像矩形框标注与质量复核。用户导入素材并设置任务标注帧率，使用画框、调整和播放中固定框动态录制完成标注；参考人工关键帧生成本地视觉候选，可选择光流跟踪或线性插帧补齐区间，并逐帧确认或拒绝。软件支持多种矩形框格式导出及配对原素材回导浏览，提供可跳过的审查步骤，定位轨迹内部缺帧、位置和尺寸跳变、低匹配分数及未确认候选，生成处理状态报告。

技术特点草案：统一任务时间线与原视频帧映射，保留人工优先及来源/审核信息，通过插件注册表扩展标注、补帧、导入、导出和审查引擎。素材在本机处理；当前没有账号服务、云推理、已训练的大模型或后台数据库。

界面的「AI 关键帧标注」目前运行本地模板匹配，「AI 标注审查」目前运行本地一致性检查。申请说明必须写明实际引擎，不能宣称多模态语义审查已经上线，也不能把匹配相关性当成准确率。

## 4. 用户操作手册大纲

正式手册应使用实际软件截图和真实操作结果，建议按以下章节编写。图示可以解释步骤，不为凑页数重复截图或扩写虚构功能。

### 第 1 章：软件概述

- 软件全称、简称、版本、应用场景和主要能力。
- 完整流程：导入 → 标注 → 导出配置 → 可选审查 → 下载结果。
- 功能边界：矩形框、单素材任务、本地处理；真实多模态服务作为后续扩展。

### 第 2 章：安装、启动与工程管理

- 环境要求与双击 `启动帧序.command` / `npm run dev`。
- 本地地址、页面入口、工程打开与备份。
- 自动保存标注元数据；真实视频恢复时重新关联原文件。
- 审查处理状态通过独立报告或 ZIP 留存，刷新后可重新审查。

### 第 3 章：第一步——导入与帧切分

- 视频/图像选择、拖放、文件信息和类别设置。
- 删除未使用类别；已有标注先迁移类别，保留框与目标 ID。至少保留一个类别。
- 原视频帧率与标注帧率：60→20 的一秒 20 帧例子。
- 标注帧连续编号与原帧对应、已有标注后帧率锁定。
- 「选择标注文件」配对原视频浏览导出成果。
- 错误文件、尺寸/时长不匹配等实际提示。

截图：空白导入页；素材导入及帧切分；标注文件配对。

### 第 4 章：第二步——标注、AI 关键帧与补帧

- 播放、帧号、时间线、逐帧跳转和多目标选择。
- 拖动画矩形、四角调整、缩放和平移；数字坐标统一应用或还原；跨帧/对象复制粘贴。
- 第二步管理类别名称与颜色、增删迁移；独立对象名称/类别、锁定/隐藏、出现区间和可撤销删除。
- 第二步设置动态框宽高；播放中按住鼠标录制每个标注帧。
- 时间线人工/AI 建议点、最大人工间隔、均匀/已有质量信号优先、逐点跳转。建议点与已有框分别展示。
- 人工关键帧 → 按共用计划生成本地模板候选 → 确认或拒绝。人工建议点保留给实际人工框；拒绝帧阻断 AI 传播。
- 双向光流及线性插帧选择；跟丢、拒绝帧和人工纠错的处理。
- 全部对象/当前类别/当前对象三个范围；逐对象进度、跳过/失败原因，取消后不写半成品。
- 范围、来源、状态筛选，20 项分页，单条/批量确认拒绝与恢复；更新未确认候选是显式选择，保护人工、确认和拒绝记录。
- 人工纠错仅清理附近依赖的未确认段；整段动态录制和批任务可一次撤销/重做。

截图：人工框；动态框配置；AI 关键帧待确认；补帧方式与复核。

### 第 5 章：第三步——导出与结果回看

- 搜索/分组选择 COCO、YOLO、CVAT、MOT 等实际支持的 20 个适配器。
- 已确认筛选、帧图像打包、实际框数和帧数。
- 沿用第一步标注帧率；连续帧名、MOT 帧率和 CSV 时间戳。
- 可进入第四步，或跳过审查直接下载。
- 下载 ZIP 与原素材回导，说明清单在保留来源/映射中的作用。

截图：格式选择；下载结果；回导后的框叠加画面。

### 第 6 章：第四步——可选审查

为什么需要这一部：跟踪可能漂移，逐一查看全部框成本高。规则先定位反常帧，人再对照画面，减少盲目翻帧。

- 选择本地一致性检查引擎，开始或取消审查。
- 五类疑点、轨迹内部检查范围及误报可能。
- 点击疑点跳到对应帧，查看相邻帧。
- 「去修正」返回第二步；「已核对」和「忽略提示」仅改变报告处理状态。
- 修改框后报告失效，重新审查后才附入新导出 ZIP。
- 下载审查 JSON、返回导出与跳过审查。
- 审查没有覆盖的任务：未知对象、类别语义、复杂遮挡，需要后续模型和人工判断。

截图：审查入口；疑点列表与画面；已核对状态；报告失效提示；ZIP 内报告。

### 第 7 章：维护与常见问题

- 文件格式、帧率与画面对应、浏览器编码兼容、源素材重关联。
- 图像打包上限和当前恒定帧率抽帧边界。
- 确认筛选为何减少导出框数，审查提示为何不是自动认定错误。
- Git 版本恢复与工程备份。

## 5. 软件设计说明书大纲（可用于补充说明）

1. 总体架构：React 四步界面、统一工程模型、媒体帧读取器、插件注册表。
2. 工程数据：媒体、标注帧率/原帧率、类别、轨迹、矩形框、来源与复核状态。
3. 任务时间线：`media.fps`、`sourceFps`、连续帧号和取帧映射。
4. 人工与动态录制：每个任务帧记录、画面边界、鼠标样本重采样、整段撤销；建议点按最大间隔及已有质量信号规划，不自动生成已完成人工框。
5. 关键帧与补帧：本地模板匹配、双向 LK 光流、线性插帧、拒绝屏障和取消。
6. 文件模块：20 个导出器、帧图像目录、清单、原生导入及媒体配对。
7. 审查模块：只读检查、五类发现、人工处理状态、报告失效和导出附件。
8. 扩展接口：`AnnotationAssistPlugin`、`FrameFillPlugin`、`AnnotationImportAdapter`、`ExportAdapter`、`AnnotationAuditPlugin`。
9. 运行与验收：单元案例、实际界面操作、导出回导、桌面与窄屏截图。
