# 帧序：从可运行 Demo 到可长期使用的产品

更新：2026-10-08。当前 GitHub 版本为 v0.6.0，标签为 `v0.6.0-github`。类别/对象编辑、多对象批处理、连续画同类目标和人工 → AI → 补帧顺序复核已完成；后续目标仍需独立验收，不能用已发布的版本号代替完成证据。

## 先明确产品的核心

用户需要可靠的标注数据，原因是这些数据要用于训练、评估或复查。重复画框耗时间，所以用跟踪和模型减少重复劳动；自动结果可能错，所以保留人工锚点、来源和复核；数据要进入别的工具，所以统一坐标、帧号和导出格式。

因此，产品核心是：**让用户以更少操作，得到可检查、可修改、可导出的标注数据。** 每个新功能都应说明减少了哪一种成本：操作时间、修正时间、数据丢失风险或格式转换成本。

当前“AI 关键帧标注”实际上使用本地像素模板匹配：记住人工框中的外观，在附近帧寻找相似位置。光流则跟踪局部图像点的运动。它们不会根据类别名称理解物体，也不能自动发现从未标注的新目标；第四步目前是本地规则检查。未来接入的真实模型应显示模型名、版本、处理范围和数据去向。

## 模型该怎么选

先分清两个问题：**找到画面中的新对象**需要检测/定位能力；**沿视频追踪一个人工指出的对象**需要跟踪能力。语言模型理解类别和场景，不等于能输出稳定、精确的像素坐标。

针对当前产品，优先评估人工提示后的跟踪器，再考虑增加新目标检测。前端只负责提示、显示候选和复核；模型服务负责加载权重、推理、取消、硬件选择与版本记录。这样不必把大模型和 GPU 依赖塞进每个用户的前端安装过程。

CVAT 将自动标注工具与模型分开组织，Label Studio 也通过 ML backend 接入模型服务；可以参考接口职责，避免照搬其全部部署复杂度：[CVAT 自动标注](https://docs.cvat.ai/docs/annotation/auto-annotation/)、[Label Studio ML 接入](https://labelstud.io/guide/ml)。

## 如何证明“好用”和“准确”

- **能否完成任务**：记录从导入到下载结果是否有阻塞、是否有数据丢失，以及恢复是否正确。
- **是否省时间**：同一批视频对比纯人工与辅助模式的总耗时，把复核和纠错时间也计算进去。
- **标注质量**：准备独立人工真值，按事先写明的 IoU 阈值统计定位结果，另记漏标、误标、ID 切换及需要人工修正的比例。
- **跨平台**：CI 负责安装、测试和构建；浏览器操作、视频解码和快捷启动仍需真实系统验收，不能仅凭 CI 宣称完全兼容。
- **格式可用**：本项目回导正确与外部软件兼容是两种验收，分别记录。

## Vibe coding 的日常工作方式

一次只给 AI 一个可验收任务：写明触发步骤、期望行为、保留哪些数据和验收条件，让它先读相关模块，再改代码、跑检查、实际操作界面，最后提交一个能独立回滚的修改。

例如：“第二步可修改类别名称；修改后所有已有轨迹和框保留，导出的类别也改变；测试重复名称和空名称；在两个目标的任务中操作验证。”这比“全面优化所有功能”更容易验收，也更容易知道哪里出了问题。

每一轮都保留四件东西：问题记录、代码差异、验证证据、发布版本。AI 可以写实现和测试，你负责确认用户流程是否正确、结果是否有用，以及这次改动值不值得上线。

暂不优先做账号、计费、多人协作、复杂微服务、所有模型同时接入。先用真实小任务把单人标注体验和数据可靠性做扎实。
