# v0.5 可用性检查与修订

日期：2026-10-08。范围：现有四步、本地矩形框工作流。保留现有框架与 20 个格式适配器。

## 为什么这样改

**类别回答“是什么”，对象回答“是哪一个”，复核回答“是否可靠”。** 为什么要分开？视频中可以有两辆同类别的车，但它们的位置和出现时间不同；改变类别名称不能改变身份，批量运行也不能只处理当前选中的那辆车。程序生成的是候选，确认、拒绝、人工修正必须作用于明确的对象与帧。

先复现 v0.4 的缺口，再按这三个关系检查导入、编辑、生成、复核、导出与恢复。此次没有换框架、增加项目看板或加入账号系统。

## 当前“AI”实际做什么

1. 人工框的中心区域生成 RGB 外观模板。
2. 到计划中的目标帧，依据前一段位移预测搜索区域，再做相似图块搜索与细化。
3. 相关性、颜色误差、位移限制通过时，返回原图像素框；分数是相关性，候选保持未确认。
4. 光流补帧另用金字塔 Lucas–Kanade、前后向检查、鲁棒位移/轻微尺度估计与外观校验；线性插帧仅计算两锚点间坐标。

**当前没有调用大模型，也不会仅凭类别名发现画面中的所有对象。** 批量是逐个处理已建立的对象，缺少人工框时跳过。模板、光流和规则审查没有经过真实数据集准确率验证，不能承诺极高准确率。引擎原理默认收起、可随时展开，界面不把模型候选显示为人工确认结果。

## 可扩展性

`core/workflow.ts` 统一范围、对象区间、人工修正、候选合并、批量复核的不变量；`core/batch.ts` 管理任务、逐对象错误与 16MB 上限帧缓存。插件仍只返回候选，不直接覆盖工程。新增模型插件可以复用范围、进度、取消、保护和复核界面，无需重新实现整套工作流。新增组件按类别/对象/生成/复核划分职责。

## 验收边界与下一阶段

这次提高的是现有矩形框闭环的可操作性和数据保护，仍是本地 demo。尚未完成：真实深度模型服务、可变帧率 PTS 精确解码、长视频后台任务、分割/关键点、多人协作、对象复杂遮挡后的重识别、外部软件逐一往返，以及独立真实视频集的质量/耗时评估。正式版应先验证一个特定场景的定位质量和人工修正时间，再扩展范围。

源码测试与页面操作记录见 [验收记录](VERIFICATION.md)。本轮的合成测试和示例 UI 结果不作为真实模型准确率指标。
