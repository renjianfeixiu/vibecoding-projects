# 帧序 FrameFlow · 产品大纲

版本：0.4，2026-10-07。第一阶段交付：本地运行的、可操作的前端 demo。

## 1. 一句话与本质

**让人决定“什么是对的”，让程序完成“重复画框”。**

为什么需要标注？训练和评估视觉模型需要可靠的参照。为什么视频标注耗时？同一对象在相邻帧反复出现，但位置会变化。为什么不能只标一帧？目标可能转弯、缩放、遮挡、消失，程序不能凭空确定它一直存在。为什么需要复核？推理结果只是候选，可靠数据必须能追溯到人的判断。

于是最小数据单位是：`媒体 → 帧/时间 → 对象 ID → 类别 → 几何位置 → 来源 → 审核状态`。播放器、模型和导出格式都围绕它工作，不各自维护一份标注。

产品定位：面向个人研究者和小团队的本地优先图像/视频标注工作台。借鉴 CVAT 的轨迹、关键帧、辅助标注和格式转换能力，首版只露出完成当前任务必需的操作。

## 2. 四步工作流

### 第一步：导入与设置

- 导入一个本地视频或图像；提供无需上传的内置示例。
- 可同时选择标注文件，在现有工作台播放叠框结果并继续修改。全部 20 种帧序导出 ZIP 使用清单恢复原始帧/像素坐标与来源；同时提供 COCO、CVAT XML、YOLO / Darknet、VOC、LabelMe JSON、MOT、帧序 CSV 的原生解析器。素材尺寸或时长不匹配时不写入工程；可先选标注或先选素材。
- 视频显示文件名、尺寸、时长；用户确认原视频帧率。浏览器不能可靠识别任意视频的真实帧率，不能偷偷用 30 FPS 冒充检测结果。
- 主要设置任务名称、帧切分（标注帧率）和类别；原视频帧率可展开确认，框大小与 AI 关键帧间隔在第二步设置。
- 类别可删除。已关联标注时先选择迁移类别再删除，保留框和目标 ID；至少保留一个类别，最后的旧类别可以添加新类别后删除。
- 标注帧率决定整个任务的连续帧号、动态录制、补帧与导出。原视频 60 帧/秒设为标注 20 帧/秒时，一秒有 20 个标注帧，取原帧 0、3、6…57；保存两种帧率用于准确回看。AI 关键帧间隔是独立参数；已有标注后锁定任务帧率，旧工程维持原时间线。
- 下一步进入统一工作台，不再创建额外的项目管理层级。

### 第二步：标注与复核

工作区：左侧大画面、目标选择、播放控制和时间线；右侧辅助操作及来源筛选、帧复核。说明默认收起。

1. **逐帧人工标注**：暂停后拖动绘制矩形；选择已有轨迹后拖动位置、修改坐标/尺寸；新轨迹有独立 ID，可切换类别。
2. **鼠标动态标注**：在第二步设置固定框宽高，播放时按住鼠标跟随目标；连续写入录制期间的所有标注帧，没有帧间隔。浏览器显示跳帧时，在两次鼠标样本之间按标注帧率重采样鼠标轨迹；它不等同于目标视觉跟踪。松开即停止录制；指针离开画面暂停写入且不连接离开期间的轨迹。框大小以原图像素为单位，画面边缘将框平移回图内。
3. **关键帧建议**：时间线显示待人工菱形点和待 AI 圆点，可点击跳帧、跳下一点。默认人工最大间隔 3 秒、可调；均匀安排，或把已有低匹配分数/拒绝候选优先交给人工，再检查人工点最大间隔。实际人工框才完成该点，AI 确认不会替代；计划目前不锁住整个后续流程。
4. **AI 关键帧标注**：人工框作为锚点；程序读取时间线共用的点位，排除人工建议点，参考最近实际人工锚点生成候选；候选单独显示，人工确认后才能作为默认导出数据。当前引擎为本地模板匹配。拒绝帧阻断传播，后续实际人工框可以恢复生成。
5. **补齐剩余帧**：用户选择算法。默认「双向光流 + 外观校验」：逐帧读取像素、金字塔 LK 前后向检查、鲁棒位移/尺度估计、人工模板校准；相邻锚点间前后双向跟踪，结果一致才融合。单锚点可以沿视频向两侧跟踪，外观校验失败或遇到拒绝帧就停止。可选「线性插帧」仅在两个已确认锚点之间插值坐标和尺寸；它适用于平稳运动，不检查像素。两种结果均待人工复核。
6. **复核与修正**：人工、辅助、补帧分别筛选；补帧行显示光流或插帧来源。点击帧跳转；确认或拒绝候选；修改产生人工版本。算法不覆盖人工框，也不把旧补帧结果用作新锚点。
7. 撤销/重做，自动保存标注元数据，下载工程备份；重新打开本地视频需用户重新选择原文件。

### 第三步：导出

- 选择格式、是否仅包含已确认结果、是否同时打包帧图像。所有格式沿用第一步的标注帧率与帧号，不再次采样；未标注的帧不生成假框。
- 下载 ZIP；包括格式文件、类别映射、来源与审核 sidecar、导出说明。标准格式不能表达的字段保存在 sidecar，不能静默丢弃。
- 导出结果可在第一步「选择标注文件」直接选择 ZIP，搭配原视频回看；预览复用播放器和时间线。标准图像格式本身没有轨迹 ID 时，不凭空推断跨帧身份。
- 显示实际框数、帧数、待复核数，空工程不能导出为“完成”。

### 第四步：审查（可跳过）

- 可从导出配置进入「AI 标注审查」，或直接跳过下载。复用现有画布查看疑点，去修正返回第二步，之后重新审查、返回第三步导出。
- 当前运行本地一致性检查：轨迹内部空缺、位置/尺寸突变、低匹配分数、未确认候选。缺帧提示只覆盖已有轨迹的标注区间，尊重拒绝帧；未知对象和类别语义需后续多模态插件。
- 审查提示为疑点，人工选择已核对/忽略，不自动修改或确认框。修改标注、帧映射或类别后报告失效；有效报告可单独下载并附入 ZIP。
- 报告覆盖当前工程，导出主体仍按确认状态筛选。界面不把「未发现本轮规则疑点」写成所有标注正确。

## 3. 本次 demo 与完整产品的边界

| 能力       | 本次可实际操作                         | 后续插件/服务                      |
| ---------- | -------------------------------------- | ---------------------------------- |
| 媒体       | 单视频、单图像、内置动画示例           | 多文件批次、长视频分块、精确抽帧   |
| 标注       | 矩形框、多轨迹、来源与确认状态         | 多边形、掩码、关键点、旋转框       |
| 动态模式   | 第二步配置固定框，播放中连续记录所有帧 | 压感、多人快捷协作                 |
| 关键帧辅助 | 真实本地图像模板匹配，按间隔生成候选   | 多模态服务 + 专用定位/分割模型     |
| 补帧       | 可选双向光流跟踪或线性插帧             | SAM 系列/专用深度跟踪器            |
| 质量       | 人工审核、前后向一致性、外观失配停止   | 独立评估集、遮挡重识别、切镜头检测 |
| 持久化     | 浏览器本地元数据、工程 JSON 备份与恢复 | SQLite、原文件资产管理             |
| 格式       | 常用矩形框格式的适配器                 | 分割、姿态、三维任务的完整格式矩阵 |

demo 的模板匹配与光流都读取实际图像，不使用示例对象坐标作为预测，不伪造模型调用。光流能跟随局部非直线运动和轻微尺度变化，仍依赖纹理与外观稳定；严重旋转、快速位移、同类目标交叉和遮挡重识别需更强模型。相关性分数不是正确率，也不是经过校准的概率。内置示例只帮助验证交互和流程，不证明真实场景效果。

## 4. 怎样实现“还不错的准确率”

为什么不让大模型逐帧直接报坐标？语言理解和精确定位是不同问题，逐帧独立推理还可能让对象 ID 跳变。可实现的生产方案：

1. 人工选择对象、框、类别及必要的正负点，建立可靠锚点。
2. 多模态模型解释对象和场景、选择待标类别，输出结构化候选及不确定性。
3. 专用检测/分割模型给出位置；视频跟踪模型传播同一对象。SAM 2 已提供视频提示和传播接口，可作为成熟接入起点，并不意味着任意视频都准确。
4. 每隔 N 帧进行图像重新定位，用新人工锚点约束漂移；检测到镜头切换、遮挡、低质量匹配时停止传播并请求人工补点。
5. 已确认锚点之间补帧；算法不跨越对象消失的段落。
6. 人工优先检查低质量段，并抽检高质量段，避免只复核低分而漏掉自信的错误。

首轮验收先限定一个场景（例如固定机位单目标），建立独立人工真值集并保留测试视频。建议目标是目标框 IoU≥0.75 的帧占比≥90%、漏标率≤5%、ID 切换单独统计、人工修正时间比纯手工减少≥50%。这些是待评估目标，不能写成已达成指标。记录检测召回、IoU 分布、每分钟人工耗时、推理成本和时延，并覆盖遮挡/缩放/切镜头子集。

本轮前端不训练模型、不下载大权重、不填入第三方密钥。真实多模态模型的准确率要在后端接入和真实数据评测后才能确认。

## 5. 导出格式路线

“所有常用格式”必须跟任务类型匹配：矩形框无法凭空生成实例掩码、语义分割图或骨架。

| 格式                                                                       | 本次矩形框实现           | 字段与限制                                                |
| -------------------------------------------------------------------------- | ------------------------ | --------------------------------------------------------- |
| FrameFlow JSON                                                             | 工程完整备份，可重新导入 | 对象、所有来源、确认/拒绝状态、参数；不含原视频二进制     |
| COCO Detection JSON                                                        | 是                       | `images/categories/annotations`，`bbox=[x,y,w,h]`，无掩码 |
| Ultralytics YOLO / Darknet YOLO TXT                                        | 是，两种目录布局         | 0-based 类别，归一化中心/宽高；data.yaml 或 obj.data      |
| Pascal VOC XML                                                             | 是                       | 每帧 XML；像素坐标；额外来源在 sidecar                    |
| CVAT for images / CVAT for video XML 1.1                                   | 是，分别可选             | 图像 image / 视频 track；稀疏视频框的 outside 断点        |
| LabelMe JSON / MIT LabelMe XML                                             | 是，分别可选             | rectangle / 四角多边形表示矩形                            |
| Datumaro JSON                                                              | 是，bbox 子集            | 标签索引、图像尺寸、来源和轨迹属性                        |
| VIA 2 JSON / Label Studio JSON                                             | 是                       | 矩形区域；Label Studio 含配套标注配置                     |
| Apple Create ML JSON                                                       | 是                       | 像素中心坐标/宽高                                         |
| Open Images V6 CSV / KITTI Detection TXT                                   | 是，2D 框                | 归一化边界 / 像素边界；KITTI 未知三维字段不生成假值       |
| WIDER Face TXT / ICDAR 2013、2015 TXT                                      | 是，专用布局             | 人脸框 / 文字定位；专用语义需使用者匹配任务               |
| MOTChallenge TXT                                                           | 是，视频轨迹             | 1-based frame、对象 ID、左上/宽高、有效标记/类别/可见性   |
| CSV                                                                        | 是                       | 明确列名、帧编号、轨迹、像素框、来源和审核                |
| COCO Segmentation/Keypoints、YOLO Seg/Pose/OBB、Mask PNG、Cityscapes、MOTS | 后续                     | 相应几何类型实现后再添加适配器                            |

共 20 个实际导出适配器，按检测训练、标注软件、视频轨迹、专用数据集和工程/表格组织。导出图片可选；默认 ZIP 只有标注与说明，须配对同尺寸、同帧命名的原图才能训练。每个适配器声明自己的图片路径，工程 JSON 无损保留来源；通用格式通过 `frameflow-manifest.json` 保留可追溯信息。实际与 CVAT 等目标软件的往返兼容测试属于下一阶段。详见 [格式矩阵](EXPORT_FORMATS.md)。

## 6. 可扩展架构

```text
React 界面
  ├─ Import → Annotate → Export → Review（可选）
  ├─ 播放器/帧读取（MediaSource 接口）
  └─ 工程状态、撤销记录与关键帧计划
          ↓
统一 Project / Track / Annotation 数据
          ├─ AnnotationAssistPlugin → 模板匹配 / 多模态 / 检测
          ├─ FrameFillPlugin        → 插值 / 光流 / SAM 2
          ├─ ExportAdapter          → JSON / COCO / YOLO / ...
          └─ AnnotationAuditPlugin  → 本地一致性 / 后续模型
```

- 插件通过明确的类型与注册表接入，不在按钮事件中塞模型逻辑。
- 辅助插件只返回带来源的候选；人工确认由工程状态统一执行。
- 同一轨迹同一帧只允许一个有效框；人工修改优先；拒绝框保留在工程历史、从通用格式排除。
- 坐标统一使用原图像素，时间保留秒值，内部帧编号从 0 开始。导出器负责不同格式的坐标/编号转换。
- 模型调用使用后台任务和取消信号；接入服务后密钥在本地服务或后端，不能写进前端代码。
- 首版限制短片/合理帧数，避免浏览器内存无限增长；正式版抽帧进 Worker/后端，用准确的时间戳处理可变帧率。
- 后续桌面版可包 Tauri，业务核心和插件接口保持复用；先证明四步流程可用。

## 7. 分阶段交付及验收

### 阶段 A：本轮

先交付并提交大纲，然后实现前端 demo。0.2 修订验收：动态录制覆盖连续帧；框在第二步设置；两种补帧可选择；用像素测试弯曲运动与遮挡停止；20 个适配器实际导出；按参考图重做简洁页面；编译、核心检查、浏览器完整流程；Git 提交及版本标签。0.4 增加类别删除/迁移、时间线建议点、人工最大间隔、质量信号优先和统一 AI 点位；保留既有帧切分、补帧、导出和可选审查。

### 阶段 B：真实视觉模型

接入一个模型服务插件和准确抽帧服务；按单一场景建立真值集；对比手工、模板匹配、专用跟踪和多模态辅助的质量/时延/成本。达标后替换默认插件。

### 阶段 C：完整标注能力

增加分割/关键点几何类型及对应格式、遮挡/消失事件、批量资产管理和分块任务。先完成每种类型的目标软件导入/回导检查，再称为“支持”。

### 暂不加入

账号/支付、团队权限、云平台、多项目看板、3D、模型训练平台、复杂审批。它们不影响首轮标注闭环。
